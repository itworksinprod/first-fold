not fit the optional-goal comparison template. The new adapter instead accepts
an operator-selected saved article from the existing publisher registry. It
derives real publisher identity from the reviewed URL and maps every saved body
block to consecutive source IDs. No MIT labels, paragraph positions or accepted
MIT output hashes are reused for another article.

automatic story selection, full web research or independent corroboration.
The saved source has not been refreshed for this trial.

The generic fact-summary instructions are adapted only to label the input as
publisher passages, avoid external-verification claims, preserve absolute dates,
and permit a supported next step or limitation rather than forcing a hypothetical

## Budget and authority

- Exactly one possible writer request, existing Cloudflare GPT-OSS-120B model,
  at most 2,400 output tokens, 90-second timeout.
- Up to four existing isolated source checks, Llama, 600 tokens each,
  30 seconds per request. Headline and all three body fields are included.
- At most five single-attempt calls and 4,800 requested output tokens total.
  No repair, retry, fallback, new provider, search, email or delivery connection.
- Only an owner-dispatched main-branch workflow on attempt one is admitted.
  A separately supplied SHA-256 binds the exact saved-source secret before
  provider credentials are exposed. These are operator-approved inputs, not
  an autonomous source-authentication mechanism.
- Only a one-day encrypted artifact leaves the runner; the private decryption
  key stays on Carlos's Mac. Parsed rejected outputs stay inside that encryption
  for diagnosis rather than being printed or silently repaired.

Replay covers exact request hashes and captured parsed responses. Raw provider
HTTP response bytes are not retained; a recorded response hash must not be
described as independent replay of those original bytes. Responses that fail in
the shared adapter before yielding a parsed payload may not be replayable.

The workflow does not verify account subscription status. It uses the existing
provider path without changing plans or enabling billing; free allocation can
be exhausted. A provider refusal stops the attempt, never upgrades the account.

## Unchanged success requirements

The body must be 110–225 words, excluding the headline. Output is plain text,
with the four expected fields and 1–4 complete sentence units per body field.
Publisher attribution, the 12-contiguous-word originality guard, response
completeness, exact request provenance and four source-support reviews remain
mandatory. Every displayed unit enters review; there is no separately unreviewed
prose field. Structural sentence checks do not prove grammatical completeness or
atomic claims; independent review must inspect every clause.

A workflow pass means only `awaiting-independent-review`. Before accepting any
preview, verify run/revision/artifact identity, decrypt locally, replay exact
requests and parsed responses, and independently inspect the complete source and
draft for factual scope, dates, conditions, material omissions, practical
usefulness, redundancy and readability. Source fidelity matters here; there is
no prior draft requiring a before/after equivalence check. The experimental
source reviewer is not qualified merely because all booleans are positive.

Any held result remains recorded. Do not add custom corrections or regenerate
until this sample happens to pass. A successful development sample would justify
a separately selected holdout, not daily promotion.

## Rollout boundary

Local verification passed all 1,794 tests, including 30 new isolated adapter
tests. The positive synthetic replies test mechanics only; no real summary has
yet been generated by this new path. Preflight review found a response-capture
boundary that could evaluate an accessor in a noncompliant adapter's object.
A bounded descriptor-safe JSON check now rejects that object before inspection,
serialization or cloning; its regression covers accessors, functions, proxies,
cycles, exotic objects and resource bounds. This was an adapter correctness
finding, not a demonstrated native JSON-provider exploit. Independent re-review
cleared the fix and reran all 125 workflow-selected tests successfully. No other
preflight blocker was found. This is code-test clearance, not output approval.
